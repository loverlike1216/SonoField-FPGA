## 已关闭的阻塞

板载 USB-UART 已枚举为 COM3，Silicon Labs 驱动版本 11.6.0.420，设备状态 OK、ConfigManagerErrorCode=0。当前克隆及独立干净克隆均安装锁定的 pyserial 3.5；应用的端口发现函数返回 COM3，禁止打开端口的测试探针未被调用。此前 Code28/0COM 证据保持原样，属于较早快照。

新的 XSDB 2025.2 SLCR 只读检查成功。检测前后两个 Cortex-A9 均为 Running；BOOT_MODE=0x05，UART_CLK_CTRL=0x00000A02，UART_RST_CTRL=0，MIO48=0x12E0，MIO49=0x12E1。保存原始寄存器值，不据此推断已验证波特率、电压、完整板卡型号或应用身份。原 Vivado 窗口保留，专用服务器断开后停止。没有打开串口、发送字节、读取 UART FIFO、halt/reset/init、写寄存器、访问 DDR RAM、下载或修改启动介质。

使用用户提供的提取码正常访问了 2023.1 网盘资料的硬件目录。01_SCH 中原理图明确命名为 V2.0；仍未取得当前 AX701020.3.0 对应的完整资料。目录元数据不等于下载后的内容校验；服务返回的混淆 MD5 字段已标记为未经验证。仅优先检查 2023.1 硬件目录，没有声称完整读取全部六个分享。用户后续说明本地没有恢复文件，故早先“有原始文件”的表述被限定为远程参考，恢复镜像仍未验证。

## 真实目标构建

安装中的 Vitis 2025.2 平台流程先因本地后端启动条件失败；采用克隆内短临时路径和 IPv4 JVM 参数后启动成功。补齐进程 PATH 后设备树生成成功，但平台创建随后因缺失 Zynq QEMU 资源失败。这条失败路径及调用栈完整保留，没有创建空资源目录冒充修复。

通过安装目录自带的 SDT + empyro + EmbeddedSW 2025.2 原生流程，配合官方 Arm GNU 13.2.rel1，完成了 BSP 和应用的真实编译链接。工具链 ZIP SHA256 为 `51d933f00578aa28016c5e3c84f94403274ea7915539f8e56c13e2196437d18f`，与公开固定值一致；只解压到克隆内 build，未安装系统工具或修改全局 PATH。

现有 service.c、service.h、generated.h、zynq_service_main.c 字节不变。新增的 xtime_l.h 兼容头直接包含 2025.2 的 xiltimer.h，沿用 BSP 提供的 XTime_GetTime 与 COUNTS_PER_SECOND。应用按候选 XSA 核对 UART1/AXI 地址后显式配置；SDT 驱动的 LookupConfig 使用基地址。115200 是候选构建参数，没有冒充当前 SD 程序的实测串口设置。

当前构建 ELF32 ARM EXEC 入口 0x0，可加载段范围分别为 [0x0,0x4604) 和 [0x8000,0x11C10)，均位于候选平台 OCM；无 DDR 加载段。包括堆栈在内的 text/data/bss 总量为 57,876 字节。三个基于真实 ELF 的破坏性副本测试分别修改 LOAD 到 DDR、入口到段外、扩大段越界，均被审计拒绝。副本仅为本地文件，从未执行。

此固件仅为既有安全禁用/状态协议服务，未链接完整轨迹或传感器运行时；不是全部 PS 功能已经上板。其初始化及握手会写 PL 安全禁用寄存器，因此不能向未知的现有程序发送 PING 来冒充只读探测。链接器的一条 RWX LOAD 警告保留；尚未证明运行内存权限、活跃 OCM 归属或物理平台匹配。**NOT_DEPLOYABLE / NOT_DOWNLOADED**。
