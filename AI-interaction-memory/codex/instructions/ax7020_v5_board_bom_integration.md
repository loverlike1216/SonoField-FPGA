# 2. AX7020 实板检测——本次最高优先级

## 2.1 检测硬件连接状态

利用 Vivado 2025.2 Hardware Manager、hw_server、XSDB，以及 Windows 可用的设备检测工具，自动完成：

1. 确认电脑是否识别 AX7020 的 JTAG。
2. 确认硬件服务器可以连接。
3. 扫描 JTAG Chain。
4. 读取 FPGA IDCODE。
5. 确认 ARM DAP 与 XC7Z020 的检测状态。
6. 记录能够真实读取的芯片标识及版本信息。
7. 检查 USB-UART 设备及实际 COM 端口。
8. 区分 JTAG、UART、其他 USB 设备。
9. 判断板卡是否存在连接异常、驱动异常或 JTAG 通信故障。
10. 保留真实检测日志。

不得将芯片 IDCODE 推断为完整封装、温度等级、速度等级或 PCB Revision。

对于不能软件读取的信息，使用实物标识和对应 Revision 的官方资料进行交叉核对；仍不能确认则标记待验证。

禁止直接尝试修改驱动、固件、EEPROM 或启动存储内容来解决枚举异常。

## 2.4 AX7020 J10/J11 管脚核验

完整建立：

`AX7020 连接器脚位 → FPGA PACKAGE_PIN → Bank → VCCO → 信号方向 → v5 信号名`

要求核对：

- J10：2×20Pin。
- J11：2×20Pin。
- 每个接口实际可用 PL IO。
- 接口编号方向及防反插。
- 连接器电源脚、GND、不可用引脚。
- 板载可能存在的 33Ω 串联电阻。
- 各 Bank IO 标准。
- 是否存在与板载其他器件复用的 IO。

输出完整 Pin Mapping 候选表，并与 v5 的需求逐一匹配。

至少包含：

- 上阵列 16 路 DATA。
- 下阵列 16 路 DATA。
- 上下阵列 CLK / LATCH / OE / RESET。
- SYNC / Heartbeat / Fault / PGOOD。
- RX Blank。
- ADC 采样、读取、BUSY 和配置接口。
- I²C 状态监测。
- 硬件安全状态返回。

先验证总数量，再验证具体引脚、电平、方向、Bank、时钟能力及布线条件。

如果 68 个名义可用 GPIO 不能满足真实接口约束，提交最小侵入的优化方案，不准擅自删除保护、监测或反馈功能。

# 3. 第一轮板级安全功能验证

在完成器件、PS/DDR、时钟与相关接口核验后，逐级执行可用的实板测试。

## Gate A：只读识别

- JTAG 识别。
- UART 枚举。
- 官方参考资料对账。
- PL/PS/DDR 配置检查。
- 可安全读取的片上状态。

Gate A 不需要下载用户逻辑。

## Gate B：最小 PL Smoke Test

只有确认待使用的 PL IO、电平和时钟后，才允许构建最小测试工程。

优先使用官方确认的板载 LED 或不连接外部负载的内部逻辑进行测试。

检查：

- PL 时钟。
- Reset。
- 计数器。
- ILA 可观察性。
- 临时 Bitstream 的加载与运行。

所有外部超声输出必须禁用，未确认的 GPIO 不得输出切换波形。

Bitstream 仅允许安全的临时 JTAG 加载，不得写入 Flash。

## Gate C：PS / DDR / UART

条件满足后依次验证：

1. PS 能正常初始化。
2. PS 时钟及复位正常。
3. DDR 初始化与受控内存测试。
4. USB-UART 与 PS UART 实际连通。
5. PC 能发送测试指令。
6. PS 能回复正确数据。

优先建立最小可靠串口通信，不急于接入全部 SonoField 功能。

## Gate D：真实 PS → AXI → PL

完成最小安全工程后，再执行：

`PC → AX7020 UART → PS → AXI → PL → AXI → PS → PC`

要求测试：

- PING/PONG。
- AXI 寄存器读回。
- 固定数据写入与读回。
- 完整帧提交确认。
- 100 次连续通信。
- 1000 次连续通信。
- 超时。
- 错包。
- 复位。
- 链路断开恢复。
- 关键寄存器状态一致性。

所有发射使能保持 OFF，不接真实超声驱动负载。

记录通信错误数、超时、结果日志及复现方法。

以上步骤应串行过门禁，不得因为 Gate A 通过就声称 Gate D 已经通过。

## P0-01：ADC 带宽问题

这是优先处理的架构兼容问题。

当前 AD7606B 在 40kHz 下的模拟带宽存在明显限制。

正式对比：

- AD7606B。
- AD7606C-16。
- 其他确有必要的 8 通道同时采样 ADC 候选。

重点验证：

1. 40kHz 附近模拟输入带宽。
2. 幅值与相位失真。
3. 八通道同步采样能力。
4. 通道间相位匹配。
5. ADC 输入电压范围。
6. 采样率及数据吞吐。
7. SNR、动态范围与校准误差。
8. RX 前端与 ADC 的带宽匹配。
9. FPGA GPIO 数量。
10. 与既有 ADC RTL 的兼容性。
11. BOM 成本、库存和封装。
12. 配置方式与实际软件复杂度。

重点评估 `AD7606C-16` 的高带宽模式。

官方资料显示该系列支持每通道 220kHz 高带宽选项，但必须核实是否需要软件模式和专门的寄存器配置。

不能因为它与 AD7606B 引脚兼容就认定可以直接替换。

优先选择不改变“8RX → 1 个同步 ADC → FPGA”系统结构的方案。

若证据足以确定最佳选型，可将其列为新版 BOM 的推荐器件，并提供完整选型理由。

如需更改既有 ADC 数据接口或数字模块，只允许做隔离的新板级适配候选，不得未经批准重写原数字核心合同。

完成后将该问题提交独立 Review，等待正式选型批准后再冻结。

## P0-02：超声驱动硬件关断

重点解决：

- SN74LVC595A 的 OE 是高阻，不等于固定低电平。
- 清零移位寄存器不自动清零输出锁存器。
- TC4427A 没有独立 EN。
- FPGA 掉电后信号可能进入不确定状态。
- 排线脱落或一侧电源异常可能造成驱动误动作。

设计可以由真实器件实现的默认关闭链路。

包括：

- 输入下拉或定义的安全偏置。
- 上电禁止驱动。
- 电源失效禁止驱动。
- 未配置 FPGA 时禁止驱动。
- Watchdog 硬件关断。
- Emergency Stop。
- 独立上下阵列关断。
- 恢复供电后必须受控重新使能。

不能只在 RTL 内增加 OE 信号就宣布安全。

要求输出真实门级逻辑、电源时序和故障矩阵，并对各类状态做仿真。

没有实体驱动 PCB 时，明确标记硬件验证 `NOT_RUN`。

## P0-03：电源与浪涌保护

重新设计并核算：

- 12V 输入。
- XT30 连接器。
- Fuse。
- TVS。
- TPS25947 eFuse。
- DC/DC。
- LDO。
- TC4427A 供电。
- PGOOD/FAULT。
- 欠压、过压、过流及热保护。

尤其核查：

`SMBJ20A` 的最坏情况钳位电压与 `TPS25947` 最大允许电压的关系。

不能只比较 TVS 标称反向工作电压，必须检查实际浪涌条件、电流、线路寄生参数、保护器件响应与最坏情况电压。

核算每个阵列：

- 最小/最大电流。
- 静态电流。
- 动态充放电电流。
- 启动浪涌。
- 峰值负载。
- eFuse 限流电阻。
- 电流检测量程。
- PCB 铜箔电流能力。
- 驱动热耗。
- 电源过冲。
- 上下板独立掉电行为。

不能把 TPS25947 的器件最大电流能力当作已经配置的限流值。

### 独立供电强制要求

上阵列必须有 `UP_PWR_IN`。

下阵列必须有 `DN_PWR_IN`。

各自具有独立：

- 电源接口。
- Fuse/eFuse。
- 故障检测。
- 关断能力。
- 本地数字/模拟电源转换。

中央 ADC 板的 AUX_PWR_IN 单独评估。

AX7020 只提供数字信号与必要信号参考地，不从扩展口承担阵列功率。

必须核查地回流、连接器拔插、反向供电和 IO 回灌。

## P1-08：功率、热和电流预算
